## Findings
- [low] tests/test_hook.py:730 blocks: no. Test isolation, not a runtime defect. `monkeypatch.setattr(ws.threading, 'get_ident', ...)` patches the `threading` module itself, not a ws-local name, so for the length of each of the 4 pinned tests every caller in the process gets 7. `threading.current_thread()` reads `get_ident()` (Python 3.13 source), so a call to it under the pin returns a `_DummyThread` with ident 7 and leaves it in `threading._active` after undo. A thread started under the pin would share the temp name, and O_EXCL would then fail between threads. This is safe today because the SubagentStop path that `reviewer_stop` drives starts no thread and reaches no board, pool or logging code. (I read `subagent_stop` in hook.py. Only `stop` (hook.py:80) and SessionStart (hook.py:302) reach `board.rows`, and the only `threading`/`current_thread` use in cli/wuwei is ws.py:43.) A sturdier form would not patch at all: the test runs in the same thread as `atomic_write`, so it can plant at `f'.{copy.name}.4242.{threading.get_ident()}.tmp'`.
