# 0001. Cut release 1.2.1 before item 1068 landed

Date: 2026-10-16
Status: accepted

## Context

Items 1065 and 1067 had merged and passed every gate. Item 1068 was still in flight. The planner
asked the owner a `one-way:` question, because a published release cannot be taken back: cut
1.2.1 now with the two fixes, or wait for 1068 and ship all three together.

## Decision

The owner chose "Cut 1.2.1 now". Both fixes had passed all gates, and 1068 can ship as 1.2.2.
Release PR #1072 cut 1.2.1 from main at 2a306da.

## Consequences

- 1.2.1 carries the 1065 and 1067 fixes. 1068 waits for 1.2.2.
- The plugin copy vendored into this repository's `.claude/wuwei/`, which runs its cloud sessions,
  still said 1.1.0 and lagged main in `evidence.py`, `gh.py` and `setup.py`. Merged fixes did not
  reach the doors here, and a release did not update the copy. Item vendored-drift exists to close
  that gap: it re-vendors the copy, makes release-please bump the copy's version with the root,
  and adds a test that fails when the copy drifts from the tree.
- Reversing this means yanking the 1.2.1 tag and release, which consumers may already have pinned.
