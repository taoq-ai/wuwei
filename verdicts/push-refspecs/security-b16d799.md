## Findings
- [high] cli/wuwei/guards.py:155 blocks: yes. Failure: regression in the push door (CWE-436 interpretation conflict, CWE-693). The new `--tags` rule drops the current-branch default whenever any word is a prefix of `--tags`, including a word that git takes as the value of the option before it. git reads `--repo --tags`, `--rep --tags`, `-o --tags`, `--push-option --tags`, `--push --tag`, or a `-vo`/`-qo`/`-uo --ta` cluster as that option's value. It sends no tags and pushes the current branch. From a clone on main (the main clone in WUWEI's layout) with local main ahead, `git push --repo --tags origin` moved main under real git 2.43.0. It passes at the head; main 5fe8347 refuses it. The gate probe found 48 such commands, all refused at main and passed at the head, in 18 of 18 quotings. The `--repo` forms need nothing from the host; the `-o` forms need a host that advertises push options. Spec How this fails 3 says "a swallowed word only adds refusals"; that is false for this rule. Fix: before reading longs and positionals, skip the word after a push option that takes one. That is `-o`, a short cluster ending in `o`, and any unique prefix of push-option, repo, receive-pack, exec or recurse-submodules written without `=`. Add a real-git test for `--repo --tags origin` and `-o --tags origin` from main.

- [medium] cli/wuwei/guards.py:158 blocks: yes. Failure: a source-only refspec `main-worktree/HEAD` (or `worktrees/<id>/HEAD`) takes its destination from that worktree's HEAD, which git 2.43 resolves (remote.c match_explicit, resolve_ref_unsafe). In WUWEI's layout the main clone is on main. So `git push origin main-worktree/HEAD`, from a builder worktree or from the main clone, pushed local main to main under real git (8 probe commands, holes at main and at the head). From the main clone, `git push origin HEAD` is refused while this spelling of the same push passes. It is the same class as `@`, which this item folds in under "reads each refspec's destination the way git 2.43 does", and it needs no ref written before the call. A fix: read a source-only word's destination with `git rev-parse --symbolic-full-name <word>` at the push's directory. That gives refs/heads/main for main-worktree/HEAD, HEAD, @ and heads/main, and it also gives refs/heads/main for residual (b)'s local symref.
