# Implementation Plan: ZIRAN role audit in CI

**Branch**: `036-ziran-ci-audit` | **Date**: 2026-09-29
**Spec**: [spec.md](spec.md)

## Summary

Reuse the existing agent generator and its golden check. Record grants with ZIRAN
0.40.0, add an offline baseline consistency check and a parametrized real audit
boundary test, then wire the pinned action and those tests into the existing CI.

## Technical Context

- Python 3.11+; stdlib test utilities and pytest only.
- ZIRAN is a dev-time executable installed into a throwaway environment, not a
  WUWEI runtime dependency. GitHub Actions installs it through the pinned action.
- Baseline is deterministic version 1 JSON owned by ZIRAN, stored under `agents/`.
- Linux CI; local tests remain offline. Real subprocesses get a timeout.
- Scope: nine roles, one workflow job, one test module, two documentation edits.

## Constitution Check

Pre-design and post-design: pass. No runtime code, new adapter, guard, state key,
parser or converter is needed. Test failures precede baseline and workflow edits.
Audit exits 1 and 2 fail the job. Existing generated-agent tests detect frontmatter
drift. Reviewed baseline changes remain subject to repository review, not local
owner-approval inference. No new speculative abstraction or runtime dependency.

## Project Structure

- `tests/test_ziran_ci_audit.py`: offline golden and optional real audit cases.
- `agents/ziran-baseline.json`: generated by the released CLI.
- `.github/workflows/tests.yml`: audit job with job-scoped SARIF permission;
  run acceptance tests after the action installs ZIRAN.
- `agents/README.md`, `docs/site/security.md`: reviewed regeneration loop.
- `specs/036-ziran-ci-audit/`: spec, plan, tasks, requirements checklist.

## Implementation and Validation

1. Inspect the release's baseline JSON and action contract; install the release.
2. Write golden and clean/widened real-tool tests. Confirm missing baseline fails.
3. Generate the baseline with the real CLI and rerun boundary tests.
4. Add the pinned action with the required inputs, no failure suppression, and
   default SARIF output. Run the same tests in its environment.
5. Document regeneration, verify generated bytes are reproducible, run the full
   prescribed suite, inspect diff and check style/path hygiene.

If sandbox networking prevents installation from PyPI, use verified local release
artifacts to run the actual CLI and record the verification limitation. Never
substitute handwritten baseline data. No additional interface contracts or data
model are needed because this work consumes the release's existing format.

## Deferred

No additional S1 behavior. Hosted CI execution is verified after this worktree is
submitted by the orchestrator; this seat does not commit or push.
