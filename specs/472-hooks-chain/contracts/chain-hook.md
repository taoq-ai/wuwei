# Contract: generated chain hook scripts

Written by `adapters/vcs/git.py` into `<git-dir>/wuwei-hooks/<name>` (the worktree's own git
directory, `git rev-parse --absolute-git-dir`), mode `0o755`, through
`wuwei.workspace.atomic_write` imported inside the function (no new import on the hook
path). Rewritten on every install; never read back.

`<shim>` is `<shims>/<name>`, where `<shims>` is the `path` argument of `hooks_path` (the
workspace's `.wuwei/git-hooks`). `<hook>` is `<own>/<name>`, where `<own>` is the resolved
absolute directory of the repository's hooks. Both are embedded with `shlex.quote`.

## Names

`pre-commit`, `pre-push`, `commit-msg`, plus the name of every regular file in `<own>` that
does not end in `.sample` and does not start with `.`, when `<own>` is a directory.

## Name with a WUWEI shim (`<shim>` is a file at generation time)

```sh
#!/bin/sh
# Generated by WUWEI worktree add and init --upgrade; changes are overwritten.
stdin=$(mktemp) || exit 2
cat > "$stdin"
<shim> "$@" < "$stdin" || { status=$?; rm -f "$stdin"; exit "$status"; }
exec < "$stdin"
rm -f "$stdin"
hook=<hook>
[ -x "$hook" ] || exit 0
exec "$hook" "$@"
```

## Name without a WUWEI shim

```sh
#!/bin/sh
# Generated by WUWEI worktree add and init --upgrade; changes are overwritten.
hook=<hook>
[ -x "$hook" ] || exit 0
exec "$hook" "$@"
```

## Behaviour

- WUWEI's check runs first, with the hook's arguments and stdin; a non-zero exit is the
  script's exit and the repository's hook does not run.
- The repository's hook then replaces the shell (`exec`) with the same arguments and the
  same stdin bytes; its exit code is the script's exit code.
- Stdin is buffered to a temporary file because both programs read it (`pre-push` gets the
  ref list). Git gives `pre-commit` and `commit-msg` an empty stdin, so `cat` returns at
  once. The file is unlinked after it is opened as stdin for the `exec`.
- An absent or non-executable repository hook is skipped with exit 0, as git skips it.
- Verified in a scratch probe on git 2.50 with a relative `core.hooksPath` (`.husky`): git
  runs hooks from the worktree root, commit ran both, an allowed push passed one stdin line
  to both, a refused push stopped before the repository's hook.
