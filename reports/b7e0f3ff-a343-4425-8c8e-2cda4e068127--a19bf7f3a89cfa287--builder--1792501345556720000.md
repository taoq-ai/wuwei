**The job file shape** (read-only, `~/.claude/plugins/data/codex-openai-codex/state/<workspace>-<hash>/jobs/<id>.json`; full table in the spec)

| Field | What it holds |
|---|---|
| `status` | `queued`, `running`, `completed`, `failed` or `cancelled` |
| `phase` | `done`, `cancelled`, `failed`, `verifying` or `running` |
| `pid` | a number while running, null once ended |
| `result` | `status` (0 or 1), `threadId`, `rawOutput` (the job's final answer), `touchedFiles`, `reasoningSummary` |

The other fields are ids, paths, timestamps and texts: `id`, `kind`, `kindLabel`, `jobClass`, `title`, `workspaceRoot`, `logFile`, `sessionId`, `threadId`, `turnId`, `rendered`, `summary`, `request`, `write`, `errorMessage` and `note`. The tests build a fixture copy of this shape and never touch the live folder.

**Assumptions**
- **Asked a question:** a `completed` job whose final answer ends in `?`. The file has no field for this.
- **HANDOFF path:** the last word in the final answer that ends in `HANDOFF.md`, with link and quote marks stripped. Both a markdown link and a bare path are tested.
- **Other statuses:** `queued` and `cancelled` show as the file names them. A missing status reads `state unreadable`.
- **Relative paths:** a relative `--job` path is read from the workspace root. The planner passes absolute paths.
- **Stale jobs:** all 8 real files that say running are in phase `verifying` or `running`, and I didn't check whether their processes are still alive. A job whose process died would still read running.
- **After the PR opens:** the PR row replaces the run row, so a fix-round job on an open PR is not shown.
- **[waiting] stays:** the run row is still marked [waiting] in every job state, the complaint #1201 raised. The text names the outcome but not that it needs action. Fixing it needs a few more lines than the budget allowed.
