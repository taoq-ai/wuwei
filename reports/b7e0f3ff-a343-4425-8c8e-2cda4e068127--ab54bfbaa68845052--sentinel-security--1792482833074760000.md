The security gate's verdict on PR #1185 at head 8e626d2 is **FIX**. A failed GitHub read can now stop the tier from being raised, so a door can open with fewer gates than main would require.

**Blocking finding** (medium, `cli/wuwei/evidence.py:246`, CWE-636 not failing securely): the merged-PR read and the new deployment reads share one error handler. If the deployments list or any one status read fails, `budget()` returns no rate at all, not even the revert count. The tier is then not raised, and that empty result stays cached for a day.

- **Example:** a repository with 10 merges in 28 days, 2 of them titled `Revert "x"` (rate 0.2, over the 15 percent limit).
- **Trigger:** the deployments read is refused with HTTP 403 "Resource not accessible by integration". That is what a fine-grained token or an app without Deployments read gets, every time, not just once. A 404 on one status read does the same.
- **Effect:** main raises the tier to full, and the create, ready and merge doors require arch, quality, security and goal. At the head they require quality alone, so one quality pass opens a door main keeps shut.
- **Differential:** I ran all 263 routes in `tests/fixtures/routes.json` (sha256 unchanged) through the guards at main and at the head. With no deploy errors, 0 routes move. With the deployments read refused, 57 move: every create, ready and merge route.
- **Fix:** read the deployments in their own `try`. When that read fails, count the reverts alone with `failures(repo, merged, [])`. Add a test where the deployments read raises `GhError` and the tier is still raised. I tried this 4-line fix in a scratch copy: 0 routes move against main and 345 tests pass.

**Notes (not blocking):**
- **Read cost:** each production deployment costs one status read, with no cap below 3,000. With 3,100 production deployments, one uncached budget read made 3,031 `gh` calls. That read runs inside the PreToolUse doors on the first door check per repository per day, and on every `wuwei report --dora`, which is not cached. `hooks.json` sets no timeout, and I did not measure whether Claude Code lets a timed-out PreToolUse hook through.
- **"prod" match:** environments named `preprod`, `nonprod` or `product-docs` count as production. This can only raise a tier, never lower it.
- **Narrower revert rule:** titles like `Reverts #1`, `Reverted ...` or `Reverting ...` counted on main and no longer do, so those repositories get a lower rate. This follows the promise ("the word revert"). Removing the `\b` from the rule breaks no test.
- **Untested `inactive` skip:** removing the check still passes every test, including on a re-run in a fresh copy. No test has a green deployment later marked inactive after a failure.
- **Paging:** an error on merged pages 2 to 30 now drops the whole rate, where main's single read had counted page 1. Same policy as main, but over more reads.
