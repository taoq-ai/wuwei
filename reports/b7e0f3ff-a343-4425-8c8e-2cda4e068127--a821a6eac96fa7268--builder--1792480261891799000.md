**What I assumed** (also in the PR body):
- **Denominator:** the rate is still failures per merge, not DORA's failed deploys per deploy. That keeps the 15 percent budget's meaning, and one failure run counts once however many reruns fail.
- **Production:** an environment GitHub flags as production, or whose name contains "prod". A production environment named otherwise and not flagged would be missed.
- **Deploy state:** a deploy's state is its newest status that is not `inactive`. I assumed GitHub lists statuses newest first.
- **Restore timing:** time to restore runs from when the first failed deploy was created to when the green one was created.
- **Cost:** the budget makes one extra host call per production deploy in the window. Its result is cached for a day per repository.
- **Read failure:** if the deployments read fails, the budget gives no rate, as when the merged read fails today. The tier is then not raised.
